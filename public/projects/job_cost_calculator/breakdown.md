# Hypothesis

The goal of this project was to translate historical SLURM job resource utilisation data into estimated cloud infrastructure costs.

We developed a proof-of-concept Ruby application that analyses historical SLURM jobs to identify suitable cloud instances and estimate the cost of running those workloads. The aim was to help organisations understand the financial implications of migrating their existing HPC workloads to cloud infrastructure.

# Approach

### How it works

The application analyses job data generated by the sacct command, extracting resource requirements such as GPU usage, CPU count, memory consumption and node count.

Using this information, the tool recommends suitable cloud instances from AWS or Azure based on each job's resource requirements. It then calculates the estimated cost of running the job using the recommended instance configuration.

The application provides cost estimates for individual jobs. For example:

```bash title=perJobCosts.sh
Job 001 used 16 GPUs, 32CPUs & 4181.11MB on 4 node(s) for 167mins. Instance config of 4 p3.8xlarge would cost $159.84.
Job 002 used 0 GPUs, 4CPUs & 8.81MB on 1 node(s) for 12mins. Instance config of 1 c5.xlarge would cost $0.05.
```

It can also analyse an entire SLURM accounting archive and provide an overview of the workload and its estimated costs:

```bash title=archiveCosts.sh
Job Totals

Total completed jobs: 578
Average time per job: 27mins
Average mem per job: 623.1MB
Average mem per cpu: 77.3MB
Max mem for 1 job: 4234.07MB
Max mem per cpu: 7044.6MB

Overall best fit cost: $23153.22
Average best fit cost per job: $40.06
35 jobs requiring larger instances than base equivalent
50 jobs requiring more nodes than used on physical cluster
```

These summaries provide insight into both the overall cost of migrating a workload and the resource requirements that influence those costs.

### Key Features

The application includes several features to support workload analysis and cloud cost estimation:

- **SLURM job analysis:** Extracts resource requirements from historical SLURM accounting data.
- **Cloud instance recommendations:** Identifies suitable AWS or Azure instances based on job requirements.
- **Instance categories:** Supports GPU-optimised, compute-optimised and memory-optimised instances.
- **Cost estimation:** Calculates the estimated cost of running individual jobs and entire workloads.
- **CSV export:** Optionally exports results for further analysis and reporting.
- **Configurable analysis:** Provides options to include failed jobs, ignore node counts or use customer-facing instance names.
- **Workload summaries:** Displays job totals, average resource usage and instance summaries.

### Use Case

The tool is intended to help organisations considering migrating their HPC workloads to cloud infrastructure. By analysing existing SLURM job history, organisations can:

- Understand their actual resource utilisation patterns.
- Estimate cloud infrastructure costs before committing to a migration.
- Identify cost-effective instance types for their workloads.
- Understand how their existing workloads may translate to cloud resources.
- Plan budgets based on historical computing requirements.

This provides a more informed starting point for cloud migration decisions, using real workload data rather than relying entirely on theoretical resource estimates.

# What was learnt

This project provided experience in analysing SLURM accounting data and translating HPC resource requirements into equivalent cloud infrastructure. We gained a better understanding of how different resource requirements, such as CPU, GPU, memory and node count, influence cloud instance selection and running costs.

We also explored the differences between traditional HPC environments and cloud infrastructure, particularly how workloads that run on physical clusters can be mapped onto available cloud instance types. This highlighted the importance of understanding actual resource utilisation rather than simply matching hardware specifications.

Overall, we learnt how historical workload data can be used to make more informed infrastructure and budgeting decisions. The project demonstrated how a relatively simple analysis tool can help organisations assess the potential financial impact of moving HPC workloads to the cloud.
